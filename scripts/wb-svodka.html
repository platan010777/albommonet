📦 Сводка WB: 2 файла → 1 таблица WILDBERRIES

Wildberries разделил данные так, что названия — в одном файле, цены — в другом. Загрузите оба файла одного магазина, скрипт соединит их по «Артикул WB» (nmID) и выдаст одну плоскую таблицу: артикул, nmID, название, цена.

🔒 Всё считается прямо в браузере. Файлы никуда не отправляются.
🛡️ Названия колонок находятся автоматически по синонимам — если WB переименует «Наименование» в «Название» или «Текущая цена» в «Цена», скрипт всё равно сработает.
1 Общие характеристики — там, где НАЗВАНИЯ
Скачай в личном кабинете WB файл с названиями. Обычно он называется Общие характеристики.xlsx или Общие характеристики товаров.xlsx. Внутри — артикул продавца, Артикул WB (nmID) и наименование. Цен здесь нет.
📋
📁 Перетащите .xlsx или нажмите для выбора Файл «Общие характеристики» для магазина №1
2 Шаблон обновления цен — там, где ЦЕНЫ
В том же кабинете скачай файл с ценами. Обычно называется Обновление цен.xlsx или Шаблон обновления цен.xlsx. Внутри — Артикул WB (nmID), артикул продавца и «Текущая цена». Названий товаров здесь нет.
💰
📁 Перетащите .xlsx или нажмите для выбора Файл «Обновление цен» для магазина №1
3 Настройки (можно оставить по умолчанию)
Названия колонок находятся автоматически по синонимам. Ниже — только если хочешь вручную переопределить для конкретного случая.
❓ Что делать, если WB переименовал колонки

WB любит менять названия колонок в выгрузках. Скрипт это предусмотрел: он ищет нужные данные по списку синонимов, а не по одному точному названию. Тебе в 99 % случаев ничего делать не надо.

Пример 1. Было «Наименование» — стало «Название»

Наименование → Название скрипт всё равно найдёт ✅
✅ Наименование — колонка D (найдено по «название»)

Пример 2. Было «Текущая цена» — стало «Цена»

Текущая цена → Цена скрипт всё равно найдёт ✅
✅ Цена (Текущая цена) — колонка I (найдено по «цена»)

Пример 3. Было «Артикул WB» — стало «nmID»

Артикул WB → nmID скрипт всё равно найдёт ✅
✅ Артикул WB — колонка C (найдено по «nmid»)

❌ А если WB придумал что-то совсем новое?

Например, назвал колонку Цена, руб. с НДС — такого синонима в скрипте может не быть. Тогда:

  1. Открой файл WB и посмотри, как точно называется колонка.
  2. Впиши это название в соответствующее поле в настройках ниже.
  3. Запусти скрипт. Ручное название имеет приоритет.
💡 Если после этого в логе всё равно ❌ «не найдена» — напиши нам: добавим новый синоним в скрипт за пару минут.

Предпросмотр (первые 30 строк)

📘 Как работает этот скрипт (для любопытных и для отладки)

Проблема

Wildberries искусственно разделил данные о товарах на два файла:

  • «Общие характеристики» — есть названия, но нет цен.
  • «Обновление цен» — есть цены, но нет названий.

Сравнить цены двух магазинов напрямую по этим файлам невозможно — нужно сначала склеить их в один промежуточный файл.

Решение

  1. Скрипт находит в каждом файле шапку и колонки по названиям.
  2. Из «Характеристик» вытаскивает: Артикул продавца, Артикул WB (nmID), Наименование.
  3. Из «Цен» вытаскивает: Артикул WB (nmID), Текущая цена.
  4. Соединяет строки по Артикул WB (nmID).
  5. Выдаёт таблицу: Артикул продавца | Артикул WB | Наименование | Цена.

Что попадёт в отчёт

КатегорияЧто означает
🟢 С ценой Товар есть в обоих файлах, название + цена склеены. Это основа для сравнения с другим магазином.
🟡 Без цены Товар есть в «Характеристиках», но в файле цен его нет. Обычно это товары без активной цены или снятые с продажи. В сводке строка подсвечивается жёлтым.
⚪ Только в ценах Товар есть в файле цен, но нет в «Характеристиках». Возможные причины: nmID удалён из карточек, дубликат, ошибка WB. Такие строки идут в конце сводки, название пустое.

⚠️ ВАЖНО — про категорию «Только в ценах»

В отчёте может появиться строка «Только в ценах» с ненулевым числом (например, 56 позиций). Это значит: в файле цен есть nmID, которых нет в файле характеристик. По ним нет названия товара.

Возможные причины

  1. WB добавил новые карточки, но характеристики ещё не подгрузились в отчёт. Обычно самоисправляется через 1–2 дня — просто скачай характеристики заново.
  2. Некоторые nmID в файле цен — дубликаты или мусорные записи. WB иногда оставляет «призраки» удалённых товаров.
  3. Часть товаров есть только в WB-кабинете, но не в файле характеристик. Например, ты их завёл, но не заполнил обязательные поля — WB не отдаёт такие карточки в отчёт «Общие характеристики».

Что с ними делать

  • Скачай xlsx — эти строки будут в конце файла, в колонке «Наименование» пусто. Отфильтруй Наименование = (пусто) — увидишь все 56 строк сразу.
  • Если это реальные товары — зайди в ЛК WB, дозаполни обязательные характеристики, скачай «Общие характеристики» заново, перезапусти скрипт.
  • Если это мусор (удалённые карточки, старые дубликаты) — ничего не делай. При сравнении с другим магазином WB эти строки не помешают: у них нет названия, значит они не склеятся с товарами второго магазина и просто не попадут в итоговое сравнение.

Как быстро проверить эти 56 строк

  1. Скачай файл из этого скрипта.
  2. Открой в Excel / LibreOffice.
  3. Включи автофильтр (он уже включён).
  4. В колонке «Наименование» поставь фильтр (Пустые).
  5. Посмотри на колонку «Артикул WB (nmID)» — увидишь эти 56 nmID.
  6. Скопируй их и поищи в ЛК WB. Если найдёшь товар — дозаполни характеристики. Если нет — это мусор, игнорируй.

Что делать с результатом

  • Скачай файл, открой, автофильтр уже включён.
  • Отфильтруй «без цены» (жёлтые) — проверь, должны ли они продаваться.
  • Отфильтруй «только в ценах» — реши: дозаполнить или игнорировать.
  • Эта сводка — вход для скрипта «Сравнение двух магазинов WB».

Технические детали

  • Шапка ищется в первых 10 строках каждого листа.
  • Скрипт пробует все листы и выбирает тот, где больше совпадений.
  • Нормализация заголовков: нижний регистр, ё→е, удаление пунктуации.
  • Дубликаты nmID отбрасываются: в сводке одна строка на один уникальный nmID.
